Proposed Database Schema Options

Choose the architecture path to store permissions in PostgreSQL. Click your choice below.

A

Postgres Native String Array on User (Recommended)

Store permissions as a native Postgres text[] array directly on the User model (e.g., permissions String[] in schema.prisma). Very fast, matches current single-user-tenant linkage model, requires zero extra join tables, and extremely simple to query and cache.

B

Granular Database Relation Table (Join Table)

Create a dedicated UserPermission model referencing User and individual permission records. Follows relational normalization strictly, but increases DB query joins on every guard check, adding implementation overhead without substantial runtime benefits.

C

Tenant-Scoped Role Permission Mapping Table

Store permission arrays on a separate ClinicRole configuration table, mapping roles dynamically (e.g., VET gets permissions X, Y, Z for Clinic A, but VET gets X, Y for Clinic B). Maximum flexibility, but higher state-management complexity.
