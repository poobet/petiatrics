# Technical Specification: Phase 1 - Accounting Foundation & Chart of Accounts

**System**: Petiatrics Veterinary Clinic ERP  
**Module**: Core Accounting & General Ledger Engine  
**Compliance**: Thailand Accounting Standards & Revenue Department Tax Regulations  
**Date**: 2026-08-10  
**Status**: APPROVED  

---

## 1. Overview & Business Requirements

The objective of "Phase 1: Accounting Foundation & Chart of Accounts" is to establish the core financial ledger, standard Chart of Accounts (COA), item tax mapping rules, and double-entry validation engine for Petiatrics. 

The system must automatically record financial transactions generated by clinic operations (POS, Billing, Inventory adjustments) into immutable double-entry journal entries while ensuring strict compliance with Thai Revenue Department tax laws.

---

## 2. Parent-Child Database Schema Design

The accounting ledger is built on a relational Parent-Child model using Prisma ORM with PostgreSQL. In line with Petiatrics' system-wide precision architecture, monetary amounts are stored as **integer Satang** (`Int`), where 1 THB = 100 Satang ($100.00\text{ THB} = 10,000\text{ Satang}$).

### Schema Definitions

#### 1. Chart of Accounts (`gl_accounts`)
Stores the clinic's standard 5-category COA structure.
- `id`: UUID (Primary Key)
- `clinicId`: String (Multi-tenant isolation)
- `code`: String (e.g. `"1010"`, `"2130"`, `"4010"`) — Unique per clinic
- `name`: String (e.g. `"Cash on Hand"`, `"Output VAT Payable"`, `"Medical Revenue"`)
- `category`: Enum (`ASSET`, `LIABILITY`, `EQUITY`, `REVENUE`, `EXPENSE`)
- `accountType`: Enum (`BALANCE_SHEET`, `INCOME_STATEMENT`)
- `normalBalance`: Enum (`DEBIT`, `CREDIT`)
- `isActive`: Boolean (Default: `true`)

#### 2. Journal Entry Header (`journal_entries`)
Parent header record for every transaction.
- `id`: UUID (Primary Key)
- `clinicId`: String
- `branchId`: String
- `entryNo`: String (e.g. `"JV-202608-00001"`, `"RV-202608-00042"`) — Unique per clinic & branch
- `journalType`: Enum (`GENERAL`, `RECEIPT`, `PAYMENT`, `SALE`, `PURCHASE`)
- `documentDate`: DateTime (Date of invoice/receipt)
- `accountingDate`: DateTime (GL Posting date used for Period Closing check)
- `description`: String
- `sourceRefType`: String? (e.g. `"INVOICE"`, `"PAYMENT"`, `"STOCK_ADJUSTMENT"`)
- `sourceRefId`: String? (ID of triggering document)
- `status`: Enum (`DRAFT`, `POSTED`, `REVERSED`) — Locked once `POSTED`
- `reversedByEntryId`: String? (FK to another `JournalEntry` if reversed)
- `postedAt`: DateTime?
- `postedById`: String?

#### 3. Journal Entry Line (`journal_lines`)
Detail line items containing Dr/Cr amounts in integer Satang.
- `id`: UUID (Primary Key)
- `journalEntryId`: String (FK `journal_entries.id` ON DELETE CASCADE for DRAFTs)
- `glAccountId`: String (FK `gl_accounts.id`)
- `debitMinor`: Int (Amount in Satang, $\ge 0$)
- `creditMinor`: Int (Amount in Satang, $\ge 0$)
- `partnerId`: String? (FK `business_partners.id` for Customer/Supplier tracking)
- `taxCodeId`: String? (FK `tax_codes.id` for Tax Audit log)
- `taxBaseMinor`: Int? (Base amount before tax in Satang)
- `taxAmountMinor`: Int? (Tax amount in Satang)
- `analyticAccountId`: String? (FK `analytic_accounts.id` for Department Cost Center)
- `memo`: String?

#### 4. Item Master & Tax Mapping (`products` & `item_categories`)
- `ItemType`: Enum (`STORABLE_PRODUCT`, `CONSUMABLE`, `SERVICE`)
- `ItemCategory`:
  - `defaultRevenueAccountId`: FK `gl_accounts.id`
  - `defaultCogsAccountId`: FK `gl_accounts.id`
  - `defaultInventoryAssetAccountId`: FK `gl_accounts.id`
  - `defaultTaxCodeId`: FK `tax_codes.id`
- `Product`:
  - Inherits or overrides category's default `TaxCode` and `GLAccount` relations.
  - `defaultVatType`: Enum (`VAT_7`, `NON_VAT` / `EXEMPT`)
  - `isTaxInclusive`: Boolean (Default: `true`)

#### 5. Cost Centers (`analytic_accounts`)
- `id`: UUID
- `clinicId`: String
- `code`: String (e.g., `"DEPT-OPD"`, `"DEPT-SURGERY"`, `"DEPT-GROOMING"`)
- `name`: String (e.g., `"Outpatient Department"`, `"Surgery & OR"`, `"Pet Grooming"`)
- `isActive`: Boolean

## 3. Double-Entry Validation Engine & Immutability Rules

### 1. Balance Rule Algorithm
Before any journal entry can be saved or posted, `JournalValidationEngine` verifies:
1. `lines.length >= 2`
2. Every line has $\text{debitMinor} \ge 0$ and $\text{creditMinor} \ge 0$
3. A single line item cannot contain both debit and credit $> 0$
4. Strict Balance Rule:
   $$\sum \text{debitMinor} \equiv \sum \text{creditMinor}$$
If $\sum \text{debitMinor} \ne \sum \text{creditMinor}$, execution is halted immediately with an `UnbalancedJournalEntryException`.

### 2. Accounting Period Guard
Before posting, the engine verifies that the `AccountingPeriod` for `accountingDate` has `status == 'OPEN'`. If `CLOSED`, a `ClosedAccountingPeriodException` is raised.

### 3. Immutability & Reversal Function
- **Immutability Lock**: Entries in `POSTED` status cannot be edited or deleted by any API mutation.
- **Reversal Entry**: To correct a posted entry:
  1. A new journal entry is created with status `POSTED`.
  2. Original lines are duplicated with **swapped `debitMinor` and `creditMinor`**.
  3. Original entry is updated to `status = REVERSED` with `reversedByEntryId` linked to the reversal entry.

## 4. Thai Tax Engine & VAT Inclusive Calculation

### 1. Tax Classification
- **VAT 7% (`VAT_7`)**: Medical check-ups, diagnostics, surgical services, medical equipment, and human medicines used for animal care.
- **NON-VAT Exempt (`NON_VAT`)**: Registered veterinary medicines (exempt under Thai Revenue Code Sec. 81/1) and pet food.

### 2. VAT Inclusive Formula (Satang Integer Precision)

$$\text{baseAmountMinor} = \text{Math.round}\left(\text{totalPriceMinor} \times \frac{100}{100 + \text{vatRate}}\right)$$

$$\text{vatAmountMinor} = \text{totalPriceMinor} - \text{baseAmountMinor}$$

### 3. Auto-Posting Actionable Example

**Scenario**: Customer pays 100.00 THB cash for a medical check-up (`SERVICE`, VAT 7%, Account `4010 - Medical Revenue`). Cash is received into Account `1010 - Cash on Hand`.

- `totalPriceMinor` = 10,000 Satang ($100.00\text{ THB}$)
- `baseAmountMinor` = $\text{Math.round}(10000 \times \frac{100}{107}) = 9,346$ Satang ($93.46\text{ THB}$)
- `vatAmountMinor` = $10000 - 9346 = 654$ Satang ($6.54\text{ THB}$)

**Generated Posted Journal Entry (`RV-202608-00012`)**:

| Line # | Account Code & Name | Debit (Satang) | Credit (Satang) | Debit (THB) | Credit (THB) |
|---|---|---|---|---|---|
| 1 | `1010 - Cash on Hand` | **10,000** | 0 | 100.00 | 0.00 |
| 2 | `4010 - Medical Revenue` | 0 | **9,346** | 0.00 | 93.46 |
| 3 | `2130 - Output VAT (Tax Payable)` | 0 | **654** | 0.00 | 6.54 |
| **Total** | | **10,000** | **10,000** | **100.00** | **100.00** |

## 5. Analytic Accounting (Cost Centers)

Cost center tags (`analyticAccountId`) are applied to line items to generate departmental Profit & Loss statements (OPD, Surgery, Grooming, Hotel, Pharmacy, Admin) without bloating COA account codes.
